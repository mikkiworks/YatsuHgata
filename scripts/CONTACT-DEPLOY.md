# お問い合わせフォームの公開手順

## 構成

- `contact/index.php`：既存デザインの入力・確認・完了画面
- `contact/form.php`：入力検証、セッション、メール送信
- `contact/.htaccess`：旧 `index.html` から転送、処理ファイルへの直接アクセス制限
- `assets/css/contact.css`：手順表示、エラー、確認画面、スマートフォン向けの補助スタイル

PHP 8.1 以降を想定。データベース・Composer・メールパスワードは不要です。
Xserver の PHP `mail()` からサーバーのメール配送機能に渡します。
差出人・管理者宛先・エンベロープ送信元は `contact@yatsuhigata.com` です。
管理者通知の Reply-To は入力者、自動返信の Reply-To は管理者です。

## アップロード

1. Xserver で `yatsuhigata.com` の無料独自 SSL が有効であること、HTTPS でアクセスできることを確認します。
2. サイトの `public_html` に変更したファイルを配置します。お問い合わせへのリンクを更新した各 HTML と `assets/css/contact.css` も対象です。
3. `contact/.htaccess` もアップロードし、サーバー上の旧 `contact/index.html` は削除します。既存の `.htaccess` がある場合は既存設定を保存してから統合してください。
4. `https://yatsuhigata.com/contact/` を開きます。

`scripts/` は保守・テスト用です。公開サーバーへのアップロードは不要です。
メールアカウントのパスワードを PHP ファイルへ記載しないでください。

## 公開環境での確認

- 実在する自分のメールアドレスで入力 → 確認 → 戻って修正 → 送信 → 完了を確認。
- `contact@yatsuhigata.com` に日本語本文が届き、返信操作で入力者のアドレスが選ばれることを確認。
- 入力したアドレスへ自動返信が届くことを確認（迷惑メールフォルダーも確認）。
- 完了画面を再読み込みしても同じメールが再送されないことを確認。
- 旧 `/contact/index.html` が PHP ページに転送されることを確認。
- サーバーのエラーログにメール送信エラーがないことを確認。

PHP の送信成功はメールサーバーの受付成功です。実際の受信箱への到着は上記テストで確認します。
Xserver のメール送信ドメイン認証（SPF/DKIM）も管理画面で確認してください。

## 動作と制限

入力はサーバー側セッションで保持し、有効期限は1時間です。完了時に入力内容をセッションから消去します。
CSRF トークン、HTML エスケープ、必須・文字数・メール形式・制御文字の検証を行います。
確認を経ない送信を拒否し、同一セッションの送信処理をロックして二重送信を抑えます。

迷惑送信対策として隠し項目、入力開始から3秒の待ち時間、IP ごとに1時間5回・宛先メールごとに1時間3回、各60秒以上の送信間隔を設けています。
失敗した送信試行も制限対象です。共有回線からの問い合わせにも制限がかかる場合があります。
レート制限は PHP の一時ディレクトリーにロック付き JSON として保持し、IP・メールアドレスのハッシュと時刻のみ記録します。
書き込めない場合は送信を停止して直接メールする案内を表示します。
これは基本的な迷惑送信対策です。分散した大量送信が発生した場合は追加対策が必要です。

管理者通知が失敗すると入力を保持して再試行を案内します。
管理者通知が成功し自動返信だけ失敗した場合は完了扱いにし、再送不要と表示します。
自動返信にはユーザー入力文を転載せず、受付番号と固定文のみ送ります。
SMTP 配送は厳密な一回限りの保証ができないため、サーバー停止等の異常時は受付番号で重複を確認してください。

## ローカル検証

システムに PHP がない環境では、PHP WASM 8.3 で実行検証できます。
検証用パッケージはサイト外の一時ディレクトリーへインストールします。

```sh
npm install --prefix /tmp/yatsu-php-test --ignore-scripts --no-audit --no-fund @php-wasm/cli@3.1.55
node scripts/test-contact.mjs /tmp/yatsu-php-test/node_modules
node scripts/verify-site.mjs
```

テストは仮想ファイルシステム上のコピーでメール配送関数だけを記録用関数に差し替えます。
本番ファイルは変更せず、実際のメールも送信しません。Apache の転送・アクセス制限と実配送は本番設置後に別途確認してください。
